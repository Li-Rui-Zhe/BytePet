# 交互可靠性优化测试报告

日期：2026-10-22。范围：消息等待、甩动释放、失败消息处理、角色缩放。**本轮不改素材导入流程、要求或资源格式。**

## 修复内容

### 1. 消息等待不再被覆盖或卡住

- 角色拖动、抛出、落地及眩晕时，只允许一条明确的等待消息。
- 聊天面板显示等待状态，提供「取消等待，继续编辑」；原文保留在输入框中。
- 后续发送不会覆盖已经等待的消息，等待期间输入框与发送按钮暂停编辑。
- 动画循环在角色恢复可交互状态后统一触发发送，不再依赖落地时的一次性定时器。
- 切换人物、删除历史等流程会取消等待；各人物草稿分开保存于当前运行内存，不混入其他人物。

### 2. 甩动按近期轨迹计算

- 根据最近 100ms 的拖动轨迹计算松手速度，松手位置与最后移动位置相同也能保留有效速度。
- 停住超过采样窗口再放手视作普通放下，不沿用过期甩动速度。
- 限制最大速度，改用短时间投射距离，避免原先单位不匹配产生过大的目标位置。
- 使用 Pointer Capture，处理松手、取消、丢失捕获与组件卸载，减少拖动卡住或监听泄漏。
- 抛出目标及过渡过程均按角色当前实际尺寸限制在屏幕工作区内；普通放下恢复下落逻辑。

### 3. 失败消息和输入原文保持一致

- 删除发送前的“假已发送”用户消息。后端成功保存用户消息后，才通过开始事件通知前端展示真实消息 ID。
- 未配置 Key 等前置检查失败时，不产生未落库的聊天气泡。
- 请求失败后校对数据库历史，保留/恢复可编辑原文；不覆盖用户已经另写的下一条草稿。
- 草稿保存在当前进程内存，关闭面板再打开仍可继续编辑；不会为草稿新增数据库字段或存储文件。退出应用后不保证保留未发送草稿。
- 如果用户消息已保存、只是 AI 请求失败，该用户消息仍属于真实历史；不会假装整段请求没有发生。重试由用户主动发送，不自动消耗 API。

### 4. 缩放几何、保存和人物编辑保护

- 画面、点击区域与物理碰撞框使用同一实际尺寸，缩放时保持脚底锚点并限制完整角色在工作区内。
- 工作区过小时自动使用能容纳的尺寸，避免画面被屏幕边缘裁切。
- 大小预览仍即时生效；保存使用单通道去抖与释放/失焦/关闭面板时的补写，避免松手后又重复写入。
- 同一人物保存串行进行；迟到响应不覆盖较新的尺寸预览，不修改当前人物选择或聊天列表。
- 只有明确点击「编辑」时才初始化人物表单，调整大小或收到后台更新不会覆盖未保存的名字、描述和素材选择。
