# macOS 适配本地测试报告

日期：2026-10-25。分支：`codex/simplify-companion`。本轮只做本地改动与验证，没有暂存、提交、推送、创建标签或执行远端 Actions。

## 结论

macOS 适配代码与双架构 Actions 流程已经准备，可以进入「推送开发分支后运行 Actions」的下一阶段。不能把这份 Windows 本地测试报告称为已经完成 macOS 原生编译和真机验收。

## 适配与修复

- 新增独立 macOS 配置，基线 13.3+，保持透明、无边框、置顶和工作区显示；临时签名默认 `-`，没有引入私有 API 透明窗口依赖。当前锁定的 Tauri 2.12.4 已支持该方式。
- 加入 `.icns` 图标与独立 plist，声明菜单栏常驻与高分辨率支持，Windows 图标未被替换。
- 新增可测试的屏幕坐标计算模块。Mac 窗口覆盖主显示器可用区域，区分 Retina 物理与逻辑像素；顶部菜单栏不再错误计入底部 Dock 高度，也处理侧边 Dock、负屏幕原点及无效工作区回退。
- 前端接收明确的工作区边界，窗口、缩放、Dock 改变后刷新；相同屏幕信息不重复更新角色，隐藏时暂停周期检查。
- 菜单栏提供隐藏／恢复，避免依赖 Windows 任务栏 API；恢复、重新聚焦与素材对话框返回时重置鼠标穿透状态缓存。监听器清理异常被收口，不产生卸载后的未捕获拒绝。
- Mac 打开数据目录采用绝对系统程序路径；数据保持系统用户数据目录，Key 保持钥匙串，不写入安装包或源码目录。

## Actions 改造

- Intel／Apple Silicon 分别使用对应原生架构的 macOS 15 runner；Node 24、pnpm 10.33.2、Rust stable。
- 最小 `contents: read` 权限，不保留 checkout 凭据，不自动发布 Release。只允许手动和版本标签触发，取消同分支重复运行。
- 使用锁文件构建、按目标和部署基线隔离 Rust 缓存、检查版本／图标／plist、运行前端与原生架构 Rust 测试。
- 临时独立钥匙串专项测试，自动恢复原默认钥匙串和删除临时文件；不需要真实模型 Key。
- 打包 app 和 DMG，检查 plist、架构、可执行权限、临时签名、原生进程启动及 DMG 完整性。
- 上传 DMG、`ditto` 权限保留的 `.app.zip` 和 SHA-256 校验文件，避免直接上传 `.app` 丢失执行权限。失败时仅上传隔离启动日志。
- 新脚本与 workflow 强制 LF，`.icns` 按二进制处理，产物目录已忽略。

## 尚未验证与限制

1. 当前主机是 Windows，没有 Apple SDK，不能在本机完成真正的 macOS 编译、钥匙串和 DMG 启动测试。未为了假装完成而跳过或伪造这些结果，已把它们放入 Actions。
2. Mac 目标依赖树的本地离线检查受缺少 Apple 平台依赖缓存限制，不能把无输出解释为「macOS 没有依赖公告」。此前报告的非 Windows 依赖公告仍需跟踪。
3. 首次云端构建必须两个架构任务都成功，再从 Artifacts 下载后做实际 Mac 验收；源代码检查和进程存活不能证明全部 UI／交互正确。
4. ad-hoc 临时签名不是 Developer ID 签名，不含 Apple 公证。Gatekeeper 可能阻止首次打开，按官方安全流程确认来源后处理，不应全局关闭保护。
5. 仅主显示器桌面区域适配，不承诺任意跨屏行走。最低支持基线为 macOS 13.3，不承诺更早系统。
6. 没有测试真实付费 API，没有修改用户真实连接或聊天数据库，没有配置或上传 Apple 证书、密码、私钥。
